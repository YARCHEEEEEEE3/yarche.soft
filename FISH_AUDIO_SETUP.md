# Fish Audio у SAKYRA

Інтеграція складається з наявного React/Vite-інтерфейсу та невеликого Node.js API. GitHub Pages продовжує роздавати інтерфейс із `docs/`; сервер запускається окремо. Для реального використання потрібні HTTPS-хостинг сервера, Supabase Auth і особистий ключ Fish Audio. Без них дизайн і режим «Голос пристрою» працюють, а AI-генерація показує стан підключення.

## Локальний запуск

Потрібен Node.js **24.5 або новіший**. Новий сервер використовує вбудований `fetch` та `--use-env-proxy`; TLS-перевірка не вимикається.

1. `npm ci`.
2. Скопіюй `.env.example` → `.env.local`, `.env.server.example` → `.env.server`.
3. У Supabase увімкни Google provider та налаштуй redirect URL, як описано в розділі Google OAuth у README. Для GitHub Pages додай точну адресу `https://yarcheeeeeee3.github.io/yarche.soft/`.
4. Заповни `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY` у `.env.local`. Ті самі URL і **публічний publishable/anon ключ**, без префікса `VITE_`, вкажи у `.env.server` як `SUPABASE_URL` і `SUPABASE_PUBLISHABLE_KEY`. Service-role ключ не потрібен.
5. Згенеруй один серверний ключ шифрування:

   ```sh
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```

   Збережи результат як `FISH_KEY_ENCRYPTION_KEY` у секретах хостингу або локальному `.env.server`. Не додавай його до Git чи `VITE_*`. Не генеруй новий при кожному запуску: старі записи потребують того самого ключа.
6. В одному терміналі виконай `npm run dev:api`, у другому — `npm run dev`. Vite пересилає `/api` на `127.0.0.1:8787`.
7. Увійди з Google на титульній. Відкрий **Налаштування → Fish Audio**, введи ключ Fish Audio й натисни **Перевірити й зберегти**.
8. В **Озвучка → Fish Audio** обери голос. «Створити прев’ю» генерує короткий текст; «Згенерувати озвучку» — текст сценарію або власний текст. Готовий файл можна прослухати та завантажити як MP3.

Файли `.env.local`, `.env.server`, `.data/` та `artifacts/` ігноруються Git. При збереженні ключа виконується перевірка списком голосів, без автоматичної TTS-генерації.

## Підключення до GitHub Pages

На хостингу Node-сервера:

- Build/install command: `npm ci --omit=dev`.
- Start command: `npm run start:api`.
- Node.js: 24.5+; `HOST=0.0.0.0`; `PORT` від хостингу.
- HTTPS через хостинг або reverse proxy. Proxy timeout має бути понад 180 секунд; відповіді MP3 — до 40 MB.
- `FRONTEND_ORIGINS=https://yarcheeeeeee3.github.io` (origin без `/yarche.soft/`). Для інших адрес додай точні origins через кому, без `*`.
- `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `FISH_KEY_ENCRYPTION_KEY` — налаштовані як вище.
- `FISH_KEY_STORE` — шлях на **постійному приватному диску**, наприклад `/var/data/sakyra/fish-keys`. Не каталог `docs/` або `public/`.
- Health check: `/api/health`. `200` означає, що необхідні параметри задано; фактичний доступ до Supabase/Fish перевіряється під час запитів. `503` означає незавершену конфігурацію.

Поточне файлове сховище й обмежувач запитів призначені для **одного екземпляра сервера**. Воно підтримує окремі ключі багатьох користувачів. Для кількох реплік потрібні спільне зашифроване сховище та спільний rate limiter. Не використовуй ефемерну файлову систему serverless-хостингу для збереження ключів.

Публічні Supabase URL і publishable key цього проєкту вже задані у `.env.production`. Для адреси API-сервера та перевизначення production-налаштувань створи ігнорований `.env.production.local`:

```dotenv
VITE_API_BASE_URL=https://YOUR-API-HOST
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR-PUBLIC-PUBLISHABLE-KEY
```

Виконай `npm run build:pages`, перевір `node scripts/check-pages.mjs` і опублікуй оновлений `docs/`. Змінні `VITE_*` входять у публічний JavaScript: там немає місця для ключа Fish Audio чи ключа шифрування. Після зміни адреси API або Supabase необхідна нова збірка. Сам `build:pages` не розгортає сервер.

## Захист і поведінка

- Сервер перевіряє Supabase Bearer token через `/auth/v1/user` на кожному захищеному запиті. Ідентифікатор власника береться лише з перевіреної відповіді, не з даних браузера. Демо-вхід не дає доступу до API.
- Ключ Fish Audio зберігається на сервері окремо для користувача, AES-256-GCM із випадковим nonce та прив’язкою до власника. Записи — `0600`, новий каталог — `0700`; запис атомарний.
- Ключ шифрування зберігай окремо від диска. Резервні копії диска також потребують захисту. Втрата ключа шифрування вимагає повторного введення Fish-ключів; їх заміна через налаштування перезаписує відповідний запис.
- GET налаштувань повертає лише факт наявності ключа. У браузері введений ключ живе тільки в полі до відправлення; після спроби поле очищується. Ключів немає у localStorage, JSON-експорті проєкту чи логах сервера.
- Усі відповіді API мають `Cache-Control: no-store`; CORS — лише для дозволених origins. Bearer-перевірка потрібна незалежно від CORS. Передача до зовнішнього сервера дозволена інтерфейсом лише через HTTPS (HTTP допускається тільки між локальними loopback-адресами).
- Вихідний endpoint зафіксовано: `https://api.fish.audio/v1/tts`. Використовуються `Authorization: Bearer …`, `model: s2.1-pro-free`, `Content-Type: application/msgpack`, `format: mp3`, `mp3_bitrate: 128`, `reference_id`, `prosody.speed`. Платна модель автоматично не підставляється.
- Список голосів: `GET https://api.fish.audio/model`, пошук, пагінація, фільтр власних голосів; показуються готові TTS-голоси. Демо-профілі не видаються за Fish-голоси. API-відмова конкретному голосу/моделі показується користувачу.
- Ліміт застосунку: **10 000 символів на запит**, без прихованого обрізання. Довгі сценарії можна озвучувати частинами через «Власний текст». Автоматичного з’єднання цих частин, зберігання аудіо в проєкті й передачі в монтаж поки немає.
- Готовий MP3 тримається в пам’яті вкладки: завантаж його перед переходом. Зміна голосу, швидкості чи тексту прибирає попередній результат. Вибір Fish-голосу й швидкість зберігаються в проєкті; ключ — ні.
- Паралельна генерація одним користувачем блокується; максимум 40 автентифікованих запитів за хвилину на користувача. TTS має timeout 180 секунд. Скасування перериває запит; якщо провайдер уже прийняв його, фактичне виконання залежить від Fish Audio. Автоматичних повторних генерацій немає.

## Перевірки

```sh
npm run test:api
npx playwright test tests/fish-settings.spec.ts tests/fish-voice.spec.ts tests/voice.spec.ts
npm run build:pages
node scripts/check-pages.mjs
```

Серверні тести виконують реальні локальні HTTP-запити з підміною Fish Audio/Supabase. Перевіряють авторизацію, ізоляцію та шифрування ключів, точний MessagePack-запит, MP3, ліміти й помилки. Браузерні тести підміняють API-відповіді й відтворюють справжній локальний MP3-тестовий тон, **не згенерований Fish Audio**. `tests/fixtures/tts-test-tone.mp3` створено через ffmpeg: синус 440 Hz, 1 секунда, MP3 128 kbps.

Окремий живий тест:

```sh
npm run test:fish:live
```

Перед запуском додай `FISH_AUDIO_API_KEY` у захищене середовище процесу (або локальний ігнорований `.env.server`). У Codex Cloud використовуй секрет із destination `api.fish.audio`; доступ до цього домену має бути дозволений. За потреби `FISH_TEST_VOICE_ID` задає конкретний голос; інакше береться перший доступний готовий голос. Тест виконує одну коротку генерацію українською та записує `artifacts/fish-live-test.mp3`. Цей тестовий ключ **не є спільним ключем сервера** і ніколи не використовується для запитів інших користувачів.

Під час реалізації живий тест **не виконано**: ключ відсутній, мережевий доступ Fish Audio потребує застосування підготовленої конфігурації. Локальні тести не підтверджують квоту, якість української вимови чи доступність конкретного акаунта Fish Audio.

Формат звірено з [офіційним Python SDK Fish Audio](https://github.com/fishaudio/fish-audio-python/tree/30d271311566b7516911234ad1d25ff65b3594ec): `resources/tts.py`, `resources/voices.py`, `types/tts.py`, README з `s2.1-pro-free`. Основна документація: https://docs.fish.audio/.
